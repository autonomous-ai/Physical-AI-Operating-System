## Required design corrections

1. **The symmetric LinkClock-refusal claim is false in current source.** The matrix's “advancing one domain alone” assertion must be narrowed. `provider_link.rs:288–301` accepts a strictly later Tokio Instant when both monotonic samples are unchanged: none of its regression/unchanged-runtime conditions fires. For example, valid samples `(R, 1_000_000, 1_000_000)` followed by `(R + 1 ms, 1_000_000, 1_000_000)` pass `retain` by source inspection. Advancing monotonic time while Tokio is fixed does fail. Submicrosecond projection can also intentionally change Instant while integer microseconds remain equal. Preserve every original LinkClock rule; do not add a production refusal to satisfy the proposed test. The fixture admission owner must independently validate exact elapsed deltas against its recorded paused-Tokio origin. Compare elapsed offsets, not equality of independently established absolute Instant epochs. Tests should distinguish this fixture check from the original LinkClock checks.

2. **Specify the owner/setup ordering behind the sample entrypoint.** Taking an already-created `Supervisor<C>` plus a `WorkerEndpoint` (plan lines 48–53) does not by itself establish that the runtime was paused, the inhibition guard installed, the ObserverScope admitted, the shared capture source initialized and transport probes attached before provider/startup work. Current construction creates the provider before spawning the worker (`early_end.rs:621–637`); Ready is sent before LinkClock/ticker setup (`provider_worker.rs:902–911`). Require an explicit fixture owner/factory sequence that installs these controls before constructing or polling provider participants; the worker entrypoint must reject a mismatched/unadmitted endpoint. This needs no Supervisor source change. Keep the thread-bound `ObserverScope` in the runtime thread's outer owner; do not put it into the existing `tokio::spawn` future, which still requires Send even on a current-thread runtime. Validate the next Moment/round/phase/delta before publication; any partial-admission failure must close/cancel that endpoint, never resume it with mixed domains.

3. **Define the tick-adapter state machine before adding it.** Require monotonic `Run → ShutdownCatchUp → ShutdownDrain → terminal/cancelled` ownership, one immutable shutdown target Moment and one inherited absolute host deadline. Run may complete only an actual original interval tick; a repeated same-Moment request cannot manufacture one. Catch-up honors still-due original ticks up to the actual root shutdown snapshot. A drain permit is explicitly cleanup work, legal only at that frozen target after catch-up, never a fake Tokio due time. Keep one outstanding permit, anchor its next host eligibility to the actual preceding worker poll, use Skip behavior rather than accumulated permits, and poll an already-due original tick before a drain permit. Both paths must enter the same original bounded body with tick-before-notice priority. The plan states the intent, but its enum alone cannot enforce these admission rules. Add the caller deadline to the control contract; do not create a fresh 300 ms allowance per poll. Host cadence samples are host-guard instrumentation, distinct from the unchanged logical sample sites.

4. **Make the receipt schema causal and complete for its limited scope.** Distinguish an actual tick's normal end, the two existing control-deferred exits, original input-slice exhaustion/backpressure, notice handling (including its early continue), actual Stop handling, and outer future return/error/panic/cancellation. `receive_inputs_inner` returns `Empty` after its eight-iteration loop (`provider_worker.rs:2502–2549`); that does not establish socket emptiness. Do not reinterpret it as such or run an extra receive. The plan's `InputDeferred` name must identify a real existing branch/budget rather than invent a new branch outcome. Record Stop versus authority revocation at their actual cause sites (`:2425`, `:2461`), not by interpreting the requested phase. A Stop observation is not the separate outer future-return receipt. Errors, dropped futures and panics cannot increment a successful-completion counter. Keep errors/panic payloads with the actual result owner, while any bounded diagnostic receipt describes their category.

For transport probes, retain a per-channel identity/direction, boot, successful send/accepted receive sequence and count. A highest sequence alone cannot prove a complete prefix. Attach before Ready; record only after `try_send` succeeds (`transport.rs:96–97`) or after all existing receive/order/age checks succeed (`:155–156`). A gap may fail the explicit fixture barrier but must not change production acceptance. Probe overflow/cancellation must latch failure synchronously, without another read, send, await or clock advance. A notice changes worker state independently of tick completion, so it needs its own state revision/receipt; an older tick receipt cannot remain a proof of later announced producer work.

## Safe separations and retained invariants

The default clock changes are narrow if implemented exactly as described: cfg-test monotonic imports for worker/LinkClock, one named helper at the existing `InputHandoff::submit` Instant read, and optional cfg-test instrumentation around existing boundaries. `transport.rs` already has the conditional ScenarioClock import. Preserve the 16-control shared budget, eight-input loop, eight-output loop, output credit/pop order, every early return/continue and the biased select. Keep the original capture-order check, strict 2,500 ms age bound and translated-Instant clamp (`provider_worker.rs:2883–2926`). Prove reversal from the live extracted body; do not reconstruct by copying an old body over another owner's current changes. Default constructors must retain their real ticker, and Gemini's feature unification must leave ordinary constructors on System capture time.

The shared capture source must be an explicit stored admitted Moment/Instant. An external thread can read that value purely; a TLS-only adapter is incorrect. Publishing the ObserverScope/capture state and immediately first-polling `tokio::time::advance(delta)` without an intervening yield is supported by pinned Tokio (`time/clock.rs:270–280` updates before `yield_now`). This is safe only under the single owner and fail-closed admission rule above; `advance().await` itself proves no participant progress.

The inhibition design is supported by pinned Tokio's actual blocking scheduler (`runtime/blocking/schedule.rs:25–26,47–48`). Its lifetime must outlast all *named* work the fixture claims to have joined. Cancellation must use a separate wakeable lane when the one Step slot is full, and the blocking guard must not exit merely because cancellation was requested. A worker-preparation harness may keep connection setup pending before any Actor exists and prove its own worker/bridge cleanup. It cannot claim all provider tasks ended while Connection's nested Actor join remains unobservable. Do not repair that limitation by editing Supervisor, using runtime background shutdown, detaching a thread, or treating root invalidation as Stop. Normal Drop/panic requires cancellation; the observer keeps its last value until named work has ended and its guard is dropped.

The shutdown mismatch is real: the root pumps at T, advances by 2 ms, then may send Stop at T+2 while the provider remains at T (`coordinator.rs:2789`, `scenario_clock.rs:386–452`, `coordinator.rs:483–510`). Catch-up to the root's already-existing T+2 snapshot is required; it is not another root advance. Once frozen, a future interval cannot read a queued Stop. The proposed host-paced drain is an explicit new fixture scheduling policy and must receive its own focused proof; it is not a property of the pure clock and cannot be smuggled into default ticks. Real service abort, Worker Stop, worker return, Actor completion, runtime thread join and sentinel process reap remain separate.

Original startup/conversation deadline origins belong to later constructor integration, not this preparation: the three-second startup deadline starts after Rig construction (`early_end.rs:689`), twelve-second conversation guard is created at the conversation call (`:730–734`), and shutdown uses the one actual 300 ms deadline (`coordinator.rs:483–489`). `Scope::enter` starts its own guard immediately. Do not resolve that mismatch by changing Scope or old bounds in the worker/Moment preparation; later integration must preserve both original phase starts without renewing budgets or imposing an accidentally earlier conversation deadline.

## Suggested immediate change

Prepare only `scenario_clock.rs`, a new adjacent Moment-between test module, and its narrow fixture-document section. Implement `between(&self, later, elapsed_from_origin)` as a pure checked value operation: validate both endpoints and shared Arc origin, require `self.elapsed <= elapsed_from_origin <= later.elapsed`, and construct through the existing checked epoch path. State explicitly that the Duration is the absolute origin offset, not an extra advance relative to the lower endpoint. Equal endpoints/inclusive bounds are valid; reversed/outside/different-origin/invalidated endpoints fail before any state change. With two valid ordered endpoints, an interior point cannot newly overflow monotone clock addition; malformed-endpoint/overflow tests should exercise validation rather than invent a reachable public state.

Required focused cases: both endpoints and a genuine interior 1 ms point; nanosecond values sharing one integer-microsecond timestamp; reversed/outside bounds; same-looking different roots; normal/panic invalidation; observer regression/foreign-origin checks still reject; repeated projection/getters perform no pump or advancement. Preserve the existing seven root tests and thirteen Moment tests byte-for-byte, plus unchanged root pump-before-2 ms advance, Shutdown freeze, original host guard and non-test cfg path. No Tokio/Gemini dependency or worker/transport change is needed for this slice.

After that is gated, implement the revised worker-local endpoint under the limits above. Treat capture-adapter/no-auto-advance ownership as named optional parts with their own W tests, not as an implicit complete runtime controller. Defer Actor/service progress, original-constructor migration and all latency claims. This sequencing advances the concrete missing clock capability without crossing owner boundaries or claiming completion of #823.
