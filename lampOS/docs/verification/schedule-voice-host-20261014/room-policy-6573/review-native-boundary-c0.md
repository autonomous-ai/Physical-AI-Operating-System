Specific coverage limits:

1. **Inherited RR20 to Other/0/nice19 is not forced by a test.** `reminders/scheduling.rs:54-70` starts a Rust thread under whatever policy the harness already has; it never establishes an RR20 precondition. The subprocess fixtures call `WorkerTransport::from_stdin_at` directly (`reminders/transport.rs:916`), bypassing `run_consumer` and scheduling. A successful ordinary-user native ARM64 run therefore cannot prove the privileged parent-to-real-child transition, or failure/readback rejection before claim/ledger opening. The existing lamp qualification already states this limit and gives parent/child inspection commands (`lampOS/docs/schedule.md:772-787`, `:834-836`). A capable Linux fixture could also cover it without a lamp: establish and assert RR20 in an isolated parent, spawn the actual entry, assert unchanged parent policy and child Other/0/nice19. Denied/partial transition and readback failure need a controlled seam if they are to become deterministic tests.
2. **Ambiguous cleanup is source-covered, but not directly exercised.** The real stop test waits for successful exit (`reminders/transport.rs:876-888`); the retention fixture manually marks its inner transport exited (`:923`). Neither forces a live TERM-resistant consumer or a `try_wait` ownership error while dropping the manager. A subprocess-contained regression could exercise that boundary and require the claim to remain unavailable to a replacement until the containing Voice process exits. The existing unconditional production-retention branch supports the intended result; this is a missing test case, not evidence that the claim currently escapes.
