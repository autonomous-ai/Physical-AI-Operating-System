## Real work and barriers

`reporting` first reads/validates config, then each cycle reads wall time and calls `read_changed` on config. It reads/caches the receipt only while enabled, accepts it only when its parsed configuration fingerprint matches, constructs the existing diagnostic, creates/recreates the real publisher as necessary, and completes its actual publication/error handling before the lifetime check and wait.

`json_file.rs:113–155` compares device, inode, size, nanosecond mtime and ctime and rechecks metadata after bounded reading. `write`, lines 196–243, performs the existing trusted-parent/regular-file validation, directory lock, exclusive temporary write, file sync, rename and parent sync. Atomic replacement changes the inode even if fast writes share a wall-clock timestamp. No artificial mtime, direct in-memory config replacement, fixed stamp or omitted fsync is needed. Keep these files and `Config::fingerprint` untouched.

The child can acknowledge a cycle only after the real publish closure and original failure handling have returned, the original lifetime branch has been evaluated, and a **positive residual wait** has been reached. A receipt says that work completed and the loop will not run again until its due time is released; it does not assert delivery or process exit. The parent still obtains the Diagnostic only from the original typed `Subscriber::recv` and checks the real `Child::try_wait`.

The selected Diagnostic declaration is `Kind::Event` (`msgs/src/lib.rs:607–610`), so it has no retained `latest` value standing in for a missed datagram. Bus publication's `Ok` can also mean no subscriber received anything (`report.rs:204–227` discards `Published` counts). Therefore an acknowledgement cannot satisfy `expect_status`; no extra diagnostic, precomputed status or synthetic delivery counter is acceptable.

The parent must return from a successful status helper only after **both** the actual matching message and the completed wait boundary are established. This holds the child before the scenario writes its next files. It drains real queued messages in order using `recv(Duration::ZERO)`; only an empty receive, with the prior cycle settled, allows the next original due step. A completed cycle with no matching message retains the original bounded search, not an invented delivery success.

**Prefer inherited piped stdin/stdout for control in this case.** The real report command does not consume stdin or emit stdout, and this test currently sets both to null; stderr is inherited and unasserted. Parent-owned pipes avoid a new Unix socket/bootstrap worker and still give a private, explicit real-child route. Use a small bounded newline protocol with version/nonce, monotone round, requested time, cycle count, actual publication outcome and next due. This is an adapter, not a new production CLI. If a Unix socket is chosen for consistency instead, reuse the same bounded framing contract; do not import Memory's scheduler or add a crate dependency merely to reuse its field names.

Reuse Memory's **patterns**: no global/env clock, pure checked offset arithmetic, strict identity/round validation, nonblocking actual I/O followed by poll under one absolute deadline, permanent close on failed control, and actual child ownership. Records already has serde/serde_json and rustix 1.1.5 with `fs`, `process`, `pipe`, `event`; dependency additions are unnecessary. Avoid per-read socket timeout mutation and the closed-peer/queued-bytes failure previously found on Darwin. A single synchronous loop needs no observer queue, reporter thread, unpark token, async stderr barrier, or IPC relay API.

At the first positive wait, accept an initial settle at logical zero and return cycle 1 / next due 1 second only after the actual initial work. Same-time or pre-due requests remain inside that wait and cannot publish. A request exactly at due releases the wait; its response is delayed until the next real cycle completes and reaches its positive wait. Reject backward time, stale rounds and jumps beyond the next due time. Never use a receipt written before the new cycle as that cycle's completion.

Each `expect_status` retains its single original **four-second** real deadline and adds a four-second logical search window; no per-frame deadline reset or unlimited virtual retries. The parent commits time only after validating the full response, then receives the actual Event. Bootstrap/control waits have real watchdogs. Preserve the original **30-second real lifetime** branch, and ensure a blocked fixture-control read cannot suspend that protection indefinitely: derive its outer bound from the original host lifetime, report control timeout as fixture failure, and never synthesize normal exit. Retain the original `Child::try_wait`/kill/wait Drop on success and panic, and establish that owner immediately after spawn so partial pipe setup cannot leak the child. Close/drop control endpoints during failure cleanup; no detached reaper. Kernel filesystem calls and actual kill/wait cannot truthfully promise a universal hard return bound.
