## How to read the waits

**T** is a sleep or paced observation in the test/helper. **D** is a deadline, timer or bounded I/O in the exercised path. **C** is a real child process’s clock. A row can have several. Guard bounds return early when their event arrives; they are not fixed delays and must not be added to the measured duration. `none` means a fast member selected with its whole module/binary, with no clock wait to migrate.

Every test name below links to its definition at the frozen source. The wait identifiers refer to detailed timer origins and semantics in `inventory.json`.

## Constraints for the next change

- Keep every identity, assertion, sample and production bound. Production entry points continue to use the system clock.
- A clock reading alone is insufficient: sleeps, Tokio timers, socket waits and child loops need a compatible wakeup/step mechanism. Advance only after current work is acknowledged and drained.
- Coordinate the design with the eighth’s supervisor clock in [#739](https://github.com/autonomous-ai/lampOS/issues/739#issuecomment-6190635224). Existing body/controller, endpoint and evaluator explicit-time seams should be reused.
- Bus expiry uses wall time and filesystem mtimes as well as monotonic scheduling. Health’s five-second test must still cross the three-second lease and prove both sources stay alive.
- The Linux capture harness already catches warm-up panics for up to three attempts. This is an inherited finding, not a proposed retry; the replacement must not hide failed setup.
- Compare complete identities and per-binary serial times before/after on the same platform. Keep real process/IPC smoke coverage and bounded host watchdogs where logical time cannot prove OS behavior.
