- `fixture_control.rs:800-805` makes the socket nonblocking before cloning it. Both read and write paths therefore perform bounded readiness waits rather than issuing a blocking socket operation after a timeout-setting race. There are no production SO_RCVTIMEO/SO_SNDTIMEO calls in Channel.
- `:732-750` uses the frame's existing absolute deadline across every partial read, Interrupted return, and WouldBlock/readiness wait. `:854-858` installs it for the complete frame operation and clears it on both success and ordinary error. `:864-866` checks the same deadline before consuming already buffered bytes, so a populated BufReader does not revive an expired exchange.
- `:762-789` rechecks remaining time for every poll, including timeout and EINTR. HUP/ERR permit one actual nonblocking I/O operation; queued bytes are consumed, read zero becomes the existing missing/truncated-frame EOF, and a write error is returned. The reviewed closed-peer paths do not loop on EOF. The invalid-descriptor case fails explicitly. There is no sleep/retry that substitutes for missing protocol work.
- `:824-850` retains only the unsent suffix after a successful short write, preserves the same absolute deadline while waiting for OUT, and returns WriteZero or the actual failure instead of reporting success. This cannot duplicate bytes or reset the exchange budget after partial progress.
- `:754-759` caps each readiness wait to signed-32-bit milliseconds while retaining the overall end. I checked the installed rustix 1.1.5 source: Darwin's libc poll adapter converts `Timespec` with millisecond ceiling; Linux uses ppoll. The exact 2,147,483,647 ms cap remains representable, and a positive sub-millisecond remaining budget is not converted to an infinite wait. The next outer deadline check handles expiration after poll returns.
- `:715-728` gives existing raw reader probes a local positive watchdog instead of configuring a closed OS socket. No-frame raw reads remain bounded; after read_frame returns, the frame deadline does not leak into the next raw probe. This test-only setter intentionally rejects `None`; existing callers all use positive `Some` values. BufReader's normal already-buffered raw-read behavior remains unchanged.
- Parent/participant failure closure, sequence validation, frame size/framing, and wire envelopes remain outside the change.
